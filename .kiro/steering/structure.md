# Structure

## Top-level layout

```
course-ai/
├── README.md                     # minimal ("ai-kit")
├── full_final_course_plan.html   # overall course plan
├── .kiro/steering/               # these steering docs
├── Kits/                         # source notebooks, grouped by topic
├── module-01-react-frontend/     # interactive learning platform (React + FastAPI)
└── module-1/ai-ops-lab/          # AI-Ops lab notebooks
```

## `Kits/` — course content

Each subfolder is a self-contained topic module of Jupyter notebooks, usually with its own `.env`, and sometimes a `README.md` / `SETUP.md` / `requirements.txt`:

- `agenticai-with-langgraph/` — LangGraph agent notebooks.
- `ai-guardrails/` — LLM security labs. Structured module: notebooks `01`–`05`, plus `security_utils/` (Python package: `config.py`, `corpus.py`, `logging_utils.py` are pre-built; `detectors.py`, `prompts.py`, `callbacks.py` are generated by running notebook cells), `tests/`, `logs/`, `pytest.ini`.
- `rag-engineering/` — RAG notebooks.
- `db/` — database / vector-store notebooks.
- `MCP/mcp-langgraph-mastery/` — Model Context Protocol lab.
- `final-package/` — assembled student bundle mirroring the modules above (`agentic-ai/`, `ai-guardrails/`, `ai-ops/`, `db/`, `rag-engineering/`, `fundamentals/`, `MCP/`, plus `course-ai-platform/`).

### Notebook naming conventions
- Numeric prefixes (`01_`, `02_`) indicate ordered sequence within a module.
- `guided_lab_*` — step-by-step guided labs.
- `*_basic` / solo-exercise / challenge notebooks — progressively less scaffolding.

## `module-01-react-frontend/` — learning platform

```
module-01-react-frontend/
├── src/
│   ├── main.tsx, App.tsx, index.css   # entry, root, global styles + theme tokens
│   ├── api/                           # axios clients + endpoint calls
│   ├── components/                    # feature components (incl. ui/ primitives, CodeCell.tsx, AppShell.tsx, SecurityBanner.tsx)
│   ├── hooks/                         # custom hooks (useApiKeys, useProgress, useApiStatus, useScreenCaptureGuard, ...)
│   ├── lib/                           # utils.ts (cn()), securityBanner.ts
│   ├── pages/                         # route-level pages
│   ├── types/                         # shared TS types
│   └── __tests__/                     # Vitest tests + setup.ts
├── backend/                           # FastAPI app: main.py, requirements.txt, tests/, .env(.example)
├── specs/                             # feature specs for this module
├── .metadata/                         # detailed product/tech/structure notes for the module
├── dist/                              # build output (generated)
├── vite.config.ts, tsconfig*.json, tailwind.config.ts, eslint.config.js, postcss.config.js
└── package.json
```

## Conventions

- **Import alias:** use `@/...` for `src/...` imports in the frontend.
- **UI primitives:** add/extend hand-owned components in `src/components/ui/` (shadcn/ui pattern) rather than pulling in a component library; use the `cn()` helper for class merging.
- **Styling:** drive colors from CSS-variable HSL tokens in `index.css`; don't hardcode raw colors.
- **State:** prefer local state + a custom hook backed by `localStorage`; do not introduce Redux/Zustand/Context providers.
- **Tests:** colocate frontend tests under `src/__tests__/`; backend tests under `backend/tests/`. Use `fast-check` (frontend) / `hypothesis` (backend) for property-based tests.
- **Backend models:** keep Pydantic request/response models inline in `main.py` (current pattern).
- **Per-kit isolation:** each `Kits/` module manages its own dependencies and `.env`; don't assume a shared root environment.
- **Generated artifacts** (`dist/`, `node_modules/`, `__pycache__/`, `logs/`, notebook-`%%writefile`d files) are not authored by hand — don't treat their absence as an error.
- **Specs:** feature specs live in `.kiro/specs/` (repo root) and `module-01-react-frontend/specs/`.
